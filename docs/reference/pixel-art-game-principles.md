# หลักการสร้างเกม Pixel Art ให้ฉาก ตัวละคร สิ่งกีดขวาง และมอนสเตอร์สมดุลกัน

เอกสารนี้สรุปหลักการออกแบบเกม 2D Pixel Art ให้ทุกองค์ประกอบ (แผนที่ ตัวละคร NPC มอนสเตอร์ สิ่งกีดขวาง ไอเทม UI) อยู่ในสัดส่วนเดียวกัน ดูกลมกลืน และเล่นได้ลื่น

---

## 1. หลักคิดหลัก: ใช้ "Tile" เป็นหน่วยวัดเดียวของทั้งเกม

ก่อนวาดอะไรทั้งสิ้น ให้ตัดสินใจ 2 อย่างนี้ก่อน แล้วห้ามเปลี่ยนกลางทาง

1. **ขนาด Tile** (เช่น 16x16)
2. **ความละเอียดภายในเกม (Internal Resolution)** (เช่น 320x180)

จากนั้นกำหนดขนาดทุกอย่างเป็น **"กี่ Tile"** ไม่ใช่ "กี่พิกเซล" เพราะเมื่อทุกอย่างอ้างอิงหน่วยเดียวกัน ความสมดุลจะตามมาเอง

---

## 2. เลือกขนาด Tile

| ขนาด Tile | ลักษณะ | เหมาะกับ |
|---|---|---|
| 8x8 | รายละเอียดน้อยมาก สไตล์ Game Boy / Atari | เกมย้อนยุค, Game Jam เร็วๆ |
| **16x16** | **มาตรฐานยอดนิยม สมดุลที่สุด** | **มือใหม่, RPG, Platformer, เกมการศึกษา** |
| 24x24 / 32x32 | รายละเอียดสูงขึ้น ตัวละครมีหน้าตา เสื้อผ้าชัด | เกมอินดี้ที่ต้องการภาพละเอียด |
| 48x48 / 64x64 ขึ้นไป | High-res pixel art | ทีมที่มีนักวาดโดยเฉพาะ |

**คำแนะนำสำหรับมือใหม่และเกมในห้องเรียน:** เริ่มที่ **16x16** เพราะวาดไว ไฟล์เล็ก และมี asset ฟรีให้ใช้มากที่สุด

> หมายเหตุ: ตัวอย่างเกมดัง เช่น Pokémon (ยุคเก่า), Final Fantasy (ยุคเก่า), Stardew Valley และ Terraria ล้วนใช้ Tile 16x16 พื้นฐาน ความต่างของ "ความละเอียดที่รู้สึก" มาจากขนาดตัวละครและการขยายภาพ ไม่ใช่ขนาด Tile

ขนาดเลขยกกำลังสอง (8, 16, 32, 64) เป็นความนิยม ไม่ใช่กฎบังคับ แต่ช่วยให้จัดการ sprite sheet และคำนวณง่าย

---

## 3. ความละเอียดภายในเกมและการขยายภาพ (Resolution & Scaling)

เกมพิกเซลควร **เรนเดอร์ที่ความละเอียดต่ำ แล้วขยายเป็นจำนวนเต็มเท่า** ด้วยวิธี Nearest Neighbor (ไม่เบลอ)

| Internal Resolution | ขยายเป็น | ตัวคูณ | Tile 16x16 แสดงได้ |
|---|---|---|---|
| 320x180 | 1920x1080 | 6x | 20 x 11.25 ช่อง |
| 480x270 | 1920x1080 | 4x | 30 x 16.9 ช่อง |
| 640x360 | 1920x1080 | 3x | 40 x 22.5 ช่อง |
| 256x144 | 1280x720 | 5x | 16 x 9 ช่อง |

**ข้อควรระวัง**
- ใช้ตัวคูณที่เป็น **จำนวนเต็ม** เท่านั้น (2x, 3x, 4x...) ไม่งั้นพิกเซลจะหนาบางไม่เท่ากัน
- ถ้าจอไม่หารลงตัว (เช่น 1366x768) ให้ใช้ **Letterbox** (แถบดำ) หรือ crop ขอบ
- ปิด Anti-aliasing / Texture Filtering ใน engine
  - Unity: Filter Mode = **Point (no filter)**, Compression = None
  - Godot: Texture Filter = **Nearest**
  - Phaser: `pixelArt: true` ใน config
  - HTML Canvas: `ctx.imageSmoothingEnabled = false` และ CSS `image-rendering: pixelated`

## 4. ตารางสัดส่วนของทุกองค์ประกอบ (อิง Tile 16x16)

ใช้เป็นแนวทางตั้งต้น ปรับตามสไตล์เกมได้ แต่ควรรักษา **อัตราส่วนเมื่อเทียบกับ Tile**

| องค์ประกอบ | ขนาดโดยประมาณ (Tile) | ขนาดพิกเซล | หมายเหตุ |
|---|---|---|---|
| **ผู้เล่น (Player)** | 1 - 2 ช่องสูง, กว้างไม่เกิน 1 ช่อง | 16x16 ถึง 16x32 | ถ้าสูง 2 ช่อง นิยมสูง 24-32 px |
| **NPC ทั่วไป** | เท่าผู้เล่น | เท่าผู้เล่น | ต่างด้วยสี/ทรงผม/เสื้อผ้า ไม่ใช่ขนาด |
| **มอนสเตอร์เล็ก** (สไลม์ ค้างคาว) | 0.5 - 1 ช่อง | 8x8 ถึง 16x16 | ต้องเล็กกว่าหรือเท่าผู้เล่น |
| **มอนสเตอร์กลาง** (หมาป่า โกเบลิน) | 1 - 2 ช่อง | 16x16 ถึง 32x32 | ขนาดใกล้เคียงผู้เล่น |
| **มินิบอส** | 2 x 2 ช่อง | 32x32 | ใหญ่กว่าผู้เล่นชัดเจน |
| **บอสใหญ่** | 3 x 3 ถึง 6 x 6 ช่อง | 48x48 ถึง 96x96 | เป็น Tile-multiple เสมอ |
| **สิ่งกีดขวางเล็ก** (ก้อนหิน พุ่มไม้ ลัง) | 1 x 1 ช่อง | 16x16 | ชัดเจนว่าชนได้ |
| **สิ่งกีดขวางกลาง** (ต้นไม้ รถเข็น) | 1 x 2 ช่อง | 16x32 | |
| **สิ่งกีดขวางใหญ่** (บ้าน ภูเขา) | 3 x 3 ช่องขึ้นไป | 48x48+ | |
| **ประตู** | 1 - 2 ช่องกว้าง, 2 ช่องสูง | 16x32 หรือ 32x32 | ผู้เล่นต้องผ่านได้สบาย |
| **ไอเทม / เหรียญ** | 0.5 - 1 ช่อง | 8x8 ถึง 16x16 | ต้องเล็กกว่าผู้เล่น และเห็นชัด |
| **ไอคอน UI** | 1 ช่อง หรือ 8x8 | 8x8 ถึง 16x16 | ใช้ Tile เดียวกับเกม ห้ามไอคอนความละเอียดต่างจากเกม |
| **Projectile / กระสุน** | 0.25 - 0.5 ช่อง | 4x4 ถึง 8x8 | |

**กฎทองของสัดส่วน**
- **ผู้เล่นคือหน่วยอ้างอิง**: มอนสเตอร์ สิ่งกีดขวาง และฉากทุกอย่างวัดเทียบกับผู้เล่น
- ตัวละครไม่ควรกว้างเกิน **1 Tile** (ยกเว้นบอส) เพื่อให้ผ่านทางเดิน 1 ช่องได้
- ตัวละครสูง 1.5 - 2 Tile เป็นสัดส่วนที่ได้รับความนิยมที่สุด เพราะเด่นจากพื้นหลังและมีพื้นที่วาดท่าทางได้ชัด
- ยิ่งเป็นศัตรูที่ "อันตราย" ยิ่งควรดู "ใหญ่" หรือมีรูปทรงเด่นกว่าผู้เล่น เพื่อสื่อสารระดับภัยคุกคามให้ผู้เล่นรู้ทันที

## 5. กฎเหล็ก: ห้ามเกิด "Mixels" (Mixed Pixels)

**Mixel** คือการเอา asset ที่มีความหนาแน่นพิกเซลต่างกันมาปนในเกมเดียว เช่น ตัวละครพิกเซลละเอียดจิ๋ว แต่พื้นหลังเป็นบล็อกใหญ่หยาบๆ

**วิธีป้องกัน**
- วาดทุก asset ด้วยแปรง **1 พิกเซล** บน Canvas ที่ตั้งสเกลเดียวกัน
- **ห้ามย่อ/ขยายภาพ asset** เพื่อให้พอดีกับแผนที่ (ถ้าต้องขยาย ให้ขยายทั้งเกมพร้อมกันด้วยตัวคูณจำนวนเต็มตอนเรนเดอร์)
- **ห้ามหมุนภาพด้วยองศาที่ไม่ใช่ 90°** เพราะจะเกิดพิกเซลเฉียง ผิดความหนาแน่น
- ถ้าใช้ asset จากหลายแหล่ง ให้ตรวจก่อนว่าขนาด Tile และความหนาเส้นเท่ากันหรือไม่
- Particle / เอฟเฟกต์ / UI ต้องวาดแบบพิกเซลเท่ากันด้วย (ไม่ใช่ภาพเบลอหรือ vector ที่ลบคม)

## 6. ความสอดคล้องของสไตล์ (Visual Consistency)

องค์ประกอบทุกชิ้นควรดูเหมือนมาจากเกมเดียวกัน

| ปัจจัย | แนวทาง |
|---|---|
| **Color Palette** | จำกัดจำนวนสี (เช่น 16-32 สี) ใช้ palette ร่วมกันทั้งเกม มีเว็บ Lospec ให้เลือก palette ฟรี |
| **เส้นขอบ (Outline)** | เลือกอย่างเดียว: ไม่มีเส้นขอบ / เส้นขอบสีดำ / เส้นขอบสีเข้มตามสีวัตถุ แล้วใช้เหมือนกันทั้งเกม |
| **ทิศแสง** | กำหนดทิศแสงเดียว (เช่น มาจากซ้ายบน) แล้วลงเงาทุก asset ตามทิศเดียวกัน |
| **ระดับรายละเอียด** | ตัวละครหลักละเอียดกว่าพื้นหลังเล็กน้อย เพื่อให้เด่น แต่ไม่ต่างกันจนดูคนละเกม |
| **ความอิ่มตัวของสี** | พื้นหลังสีนุ่ม/อิ่มตัวต่ำกว่า ส่วนตัวละคร ศัตรู ไอเทม สีสด เพื่อให้แยกชั้นออกมาชัด |
| **ความหนาเส้น** | ใช้ความหนา 1 พิกเซลสม่ำเสมอ ไม่ปนกับเส้นหนา 2-3 พิกเซลแบบสุ่ม |

## 7. การอ่านค่าได้ชัด (Readability)

ผู้เล่นต้องแยกแยะได้ทันทีว่าอะไรคืออะไร

- **ผู้เล่น** ต้องเด่นสุด (สีตัดกับพื้น มี silhouette ชัด)
- **ศัตรู** ต้องแตกต่างจากสิ่งกีดขวางและพื้นหลังชัดเจน (สีโทนอันตราย เช่น แดง ม่วง)
- **สิ่งกีดขวางที่ชนได้** กับ **ของตกแต่งที่เดินผ่านได้** ต้องดูต่างกัน (เช่น กอหญ้าตกแต่งสีอ่อนกว่า ก้อนหินที่ชนได้มีเงาและเส้นขอบชัด)
- **ไอเทมที่เก็บได้** ใช้สีสว่าง/ประกายวิบวับ หรือขยับเบาๆ เพื่อดึงสายตา
- ทดสอบ **silhouette test**: เปลี่ยนภาพเป็นสีดำล้วน ถ้ายังบอกได้ว่าเป็นตัวอะไรแปลว่าออกแบบดี
- ทดสอบ **grayscale test**: เปลี่ยนเป็นขาวดำ ถ้าแยกผู้เล่น/ศัตรู/พื้นได้ แปลว่า contrast พอ

## 8. Hitbox และการชน (Collision)

- **Hitbox ไม่จำเป็นต้องเท่าภาพที่เห็น**
  - ผู้เล่นสไตล์ top-down: ให้ hitbox เป็นเฉพาะส่วน **เท้า/ครึ่งล่าง** ทำให้เดินผ่านด้านหลังต้นไม้ กำแพงได้ดูเป็นธรรมชาติ
  - Platformer: hitbox ของผู้เล่นควรเล็กกว่าภาพเล็กน้อย (ให้อภัยผู้เล่น) ส่วน hitbox ของศัตรูที่ทำดาเมจควรเล็กกว่าภาพเช่นกัน
- **ช่องทางเดิน**: ทางเดินกว้างอย่างน้อย **2 Tile** เพื่อไม่ให้ผู้เล่นติดขัดง่าย ถ้ามีช่องแคบ 1 Tile ควรตั้งใจออกแบบเป็นจุดพิเศษ
- **มอนสเตอร์ตัวใหญ่**: ใช้ hitbox ตาม Tile grid (เช่น 2x2 Tile) เพื่อให้คำนวณง่าย
- แสดง hitbox ตอนพัฒนา (Debug Draw) เพื่อตรวจสอบเสมอ

## 9. Sprite Sheet และแอนิเมชัน

- **ทุกเฟรมในอนิเมชันเดียวกันต้องมีขนาด canvas เท่ากัน** (เช่น 16x32 ทุกเฟรม) และกำหนด **จุดอ้างอิง (Pivot)** เดียวกัน (มักเป็นกึ่งกลางด้านล่าง/เท้า) ไม่งั้นตัวละครจะสั่นเวลาเล่นอนิเมชัน
- จำนวนเฟรมแนะนำ (เกมพิกเซลมือใหม่)

| แอนิเมชัน | จำนวนเฟรม |
|---|---|
| Idle | 2 - 4 |
| Walk / Run | 4 - 8 |
| Attack | 3 - 6 |
| Hurt | 1 - 2 |
| Death | 4 - 6 |

- เดินใน 4 ทิศ (บน ล่าง ซ้าย ขวา) หรือ 8 ทิศ ใช้ได้ ส่วนซ้าย-ขวา สามารถ **flip แนวนอน** ได้ถ้าตัวละครสมมาตร
- ความเร็วอนิเมชัน 6-12 FPS ก็เพียงพอและดูเป็นสไตล์พิกเซล
- วางไฟล์ sprite sheet เป็นตารางที่แบ่งด้วยขนาดเฟรมคงที่ จัดการง่ายใน engine ทุกตัว

## 10. การจัดชั้นฉากและความลึก (Layering & Depth)

เรียงชั้นจากล่างขึ้นบน

1. **Background / Sky** (ไกลสุด)
2. **Ground Layer**: พื้น หญ้า ถนน
3. **Decoration (ใต้ตัวละคร)**: ดอกไม้ รอยทาง
4. **Objects & Characters**: ผู้เล่น NPC มอนสเตอร์ สิ่งกีดขวาง (จัดเรียงด้วยค่า **Y**: ตัวที่ Y ต่ำกว่า/อยู่ล่างจอ วาดทับตัวที่อยู่สูงกว่า เรียกว่า **Y-sort**)
5. **Foreground / Overhead**: ยอดต้นไม้ หลังคา (ผู้เล่นเดินใต้ได้)
6. **Lighting / Effects**
7. **UI** (บนสุด)

**Parallax** (พื้นหลังเลื่อนช้ากว่าฉากหน้า) ใช้ในเกม side-scroller เพื่อเพิ่มความลึก ต้องเลื่อนเป็นจำนวนเต็มพิกเซลเพื่อไม่ให้ภาพสั่น

## 11. การออกแบบด่านให้สมดุล (Level Balance)

### ขนาดและสัดส่วนของพื้นที่
- **ห้อง/ฉากเดียว** ควรเห็นได้ครบหรือเกือบครบในจอ (เช่น 20x11 Tile) สำหรับเกมแนว Zelda
- วางสิ่งกีดขวางเป็น **ช่วงๆ** มีที่ว่างให้ผู้เล่นหายใจ ไม่แน่นทุกช่อง
- ใช้หลัก **"พื้นที่เปิด 60% / สิ่งกีดขวาง 40%"** เป็นจุดตั้งต้น แล้วปรับตามแนวเกม

### การวางมอนสเตอร์
- อย่าวางมอนสเตอร์ใกล้จุดเกิด (Spawn) ผู้เล่น เว้นระยะอย่างน้อย **5-8 Tile**
- เริ่มด่านด้วยศัตรูเดี่ยว/ตัวเล็ก แล้วค่อยเพิ่มจำนวนและความแข็ง
- ให้ **พื้นที่หลบหลีก** รอบๆ ศัตรูอย่างน้อย 2-3 Tile
- บอสควรมีห้อง/สนามที่ใหญ่พอ (อย่างน้อย **3-4 เท่า** ของขนาดบอส)

### การวางไอเทมและรางวัล
- วางรางวัลหลังจุดอันตราย หรือนอกเส้นทางหลักเพื่อกระตุ้นการสำรวจ
- เว้นระยะการเก็บเหรียญให้สม่ำเสมอ ใช้เหรียญนำทางสายตาผู้เล่น (ชี้ไปทางที่ควรไป)

### ความยากเชิงพื้นที่ (Platformer)
- ระยะกระโดดสูงสุดของผู้เล่น = **หน่วยวัด** ของด่าน (เช่น กระโดดสูงสุด 3 Tile, ไกลสุด 5 Tile) แล้วออกแบบช่องว่างให้เล็กกว่าค่านี้ **เผื่อ 10-20%** เสมอ
- ทดสอบโดยเล่นจริงทุกด่าน

## 12. ความสมดุลของค่าสถานะเกม (Gameplay Stats Balance)

เพื่อให้เกม "รู้สึก" สมดุล ตั้งค่าตามอัตราส่วนเหล่านี้เป็นแนวทาง

| ค่า | แนวทาง |
|---|---|
| **HP ผู้เล่น vs. ดาเมจศัตรู** | ศัตรูทั่วไปควรทำดาเมจ 5-15% ของ HP ผู้เล่นต่อครั้ง |
| **ผู้เล่นฆ่าศัตรูกี่ครั้ง** | ศัตรูเล็ก 1-2 ครั้ง, กลาง 3-5 ครั้ง, บอส 20+ ครั้ง |
| **ความเร็ว** | ผู้เล่นเร็วกว่าศัตรูทั่วไปเล็กน้อย (110-130% ของศัตรู) เพื่อให้หนีได้ |
| **Invincibility Frame** | หลังโดนโจมตี ให้อมตะชั่วคราว 0.5-1 วินาที พร้อมกระพริบ |
| **Cooldown** | โจมตีหลัก 0.3-0.6 วิ, สกิลพิเศษ 3-10 วิ |
| **ตัวคูณความยาก** | ด่านถัดไปเพิ่ม HP/ดาเมจศัตรู 10-20% ต่อด่าน แทนที่จะเพิ่มเป็นสองเท่า |

> ตัวเลขข้างต้นเป็นจุดตั้งต้น ต้อง **Playtest** แล้วปรับเสมอ

## 13. สิ่งที่มักผิดพลาด (Common Pitfalls)

- ตัวละครใหญ่หรือเล็กเกินสัดส่วนกับ Tile จนเดินผ่านประตูไม่ได้ หรือดูเหมือนยักษ์
- ใช้ asset จากหลายแหล่งโดยไม่เช็กขนาด Tile ทำให้เกิด Mixels
- ย่อ/ขยายภาพแบบไม่เป็นจำนวนเต็ม ภาพเบลอหรือพิกเซลหนาบางไม่เท่ากัน
- ลืมปิด texture filtering ภาพนุ่มเกินไป
- ตัวละครสั่นระหว่างอนิเมชัน เพราะ pivot ไม่ตรงกัน
- สิ่งกีดขวางกับของตกแต่งหน้าตาคล้ายกัน ผู้เล่นสับสน
- ใช้สีมากเกินไป ทำให้ภาพรกและไม่เป็นเอกภาพ
- พื้นหลังละเอียดและสีจัดเกินไปจนกลืนตัวละคร
- ใช้ตำแหน่งพิกเซลแบบทศนิยม (Sub-pixel) ทำให้ภาพสั่น ควรปัดตำแหน่งตอนเรนเดอร์เป็นจำนวนเต็ม

## 14. Checklist ก่อนเริ่มโปรเจกต์ และก่อนปล่อยเกม

### ก่อนเริ่มวาด
- [ ] เลือกขนาด Tile แล้ว (เช่น 16x16)
- [ ] กำหนด Internal Resolution และตัวคูณขยาย (จำนวนเต็ม)
- [ ] กำหนดขนาดตัวละครหลัก (เป็นกี่ Tile)
- [ ] เลือก Color Palette
- [ ] เลือกสไตล์เส้นขอบและทิศแสง
- [ ] ตั้งค่า engine เป็น Nearest/Point filtering
- [ ] ทำตารางขนาดของ asset ทุกประเภท (ตามข้อ 4)

### ระหว่างพัฒนา
- [ ] ทุก asset วาดบนสเกลพิกเซลเดียวกัน (ไม่มี Mixels)
- [ ] ทุกเฟรมแอนิเมชันมีขนาดและ pivot เท่ากัน
- [ ] ตรวจ hitbox ด้วย Debug Draw
- [ ] ทดสอบ silhouette และ grayscale
- [ ] ทดสอบทางเดินแคบ ประตู ว่าผู้เล่นผ่านได้

### ก่อนปล่อยเกม
- [ ] ทดสอบหลายขนาดหน้าจอ (1080p, 720p, จอโน้ตบุ๊ก, มือถือ ถ้ามี)
- [ ] ให้คนอื่นลองเล่น และสังเกตว่าสับสนตรงไหน
- [ ] ปรับสมดุลค่าสถานะจาก Playtest จริง
- [ ] ตรวจลิขสิทธิ์ของ asset ที่นำมาใช้ (ฟรี/ต้องให้เครดิต/ใช้เชิงพาณิชย์ได้หรือไม่)

## สรุปสั้นๆ

1. **เลือก Tile 1 ขนาด** แล้วใช้ทั้งเกม (แนะนำ 16x16)
2. **ผู้เล่นคือหน่วยอ้างอิง** กำหนดขนาดทุกอย่างเป็นกี่ Tile
3. **วาดทุกอย่างบนสเกลพิกเซลเดียวกัน** ห้ามเกิด Mixels
4. **ขยายภาพด้วยจำนวนเต็ม** และปิด filtering
5. **ใช้ palette จำกัด** และสไตล์ (เส้นขอบ แสง) เดียวกัน
6. **ออกแบบให้อ่านออกทันที** ผู้เล่น ศัตรู สิ่งกีดขวาง ไอเทมต้องแยกกันชัด
7. **Playtest แล้วปรับ** ตัวเลขทั้งหมดในเอกสารนี้คือจุดเริ่มต้น ไม่ใช่กฎตายตัว
